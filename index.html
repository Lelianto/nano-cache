01 / START

Quick start

Create a cache, store a value, and retrieve it. Every method is asynchronous, so changing adapters later does not change your call sites.

typescript
import { createCache, memoryAdapter } from '@antihero/nano-cache';

const cache = createCache({
  adapter: memoryAdapter({ max: 1_000 }),
  ttl: '5m',
});

await cache.set('user:1', { name: 'Ada' });
await cache.get('user:1'); // { name: 'Ada' }
await cache.has('user:1'); // true
i
TTL accepts plain milliseconds or duration strings.

Use values such as 3000, '500ms', '10m', '2h', or '7d'.

02 / STORE

Choose an adapter

Your application code stays the same. Only the adapter decides where cached values live and how long they persist.

memoryAdapter

universal

Fast in-process LRU cache for servers, scripts, tests, and short-lived data.

localStorage

browser

Persistent browser cache with structured serialization and configurable prefixes.

sessionStorage

browser

Per-tab storage that disappears when the browser session ends.

indexedDB

browser

Large-capacity browser persistence with an automatic memory fallback.

redisAdapter

server

Shared cache across processes with native TTL and incremental key scanning.

createAdapter

custom

Wrap a database, edge store, or internal cache behind the same compact contract.

03 / MODEL

Core concepts

The useful parts are built in, but each one remains optional. Start small and add structure only where your data needs it.

01

TTL

Expiration is lazy. Stale entries are removed when read or when the adapter enumerates its keys, so no background interval is left running.

02

Namespaces

Prefix related keys automatically, allowing independent caches to share one backend without collisions.

03

Tags

Attach labels to cached entries and invalidate a related group without keeping track of every key yourself.

04

Fetch deduplication

Concurrent misses for one key share a single loader promise, reducing cache stampedes against APIs and databases.

fetch with stampede protection
const user = await cache.fetch(
  `user:${userId}`,
  () => database.users.find(userId),
  { ttl: '15m', tags: [`user:${userId}`] },
);
04 / API

Reference

A deliberately small surface area. All methods return promises, including operations backed by synchronous storage.

Method Returns Purpose
set(key, value, options?) Promise<void> Store a value with optional TTL and tags.
get(key) Promise<T | null> Read a value; returns null when missing or expired.
fetch(key, loader, options?) Promise<T> Read through the cache with concurrent request deduplication.
has(key) Promise<boolean> Check whether a non-expired entry exists.
delete(key) Promise<boolean> Remove one entry and report whether it existed.
invalidateTag(tag) Promise<void> Remove every cached entry carrying a tag.
getMany / setMany / deleteMany Promise Perform common cache operations in batches.
keys / size / stats Promise Inspect active entries and operation counters.
05 / SAFETY

Error handling

Cache outages should not become application outages. Operations remain non-throwing by default, while onError gives your logging or monitoring stack full visibility.

observe failures
const cache = createCache({
  adapter: redisAdapter(redis),
  onError: (error, { operation, key }) => {
    logger.warn({ error, operation, key });
  },
});
!
A cache is not a source of truth.

A failed write is a no-op and a failed read returns null. Keep authoritative data in your database or upstream service.
